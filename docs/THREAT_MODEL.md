# Модель угроз

[English](THREAT_MODEL.en.md)

## Активы

- API-ключи клиентов и admin-токен.
- Ключи upstream-провайдеров (только env).
- Содержимое запросов (prompt) и ответов модели.
- Конфигурация провайдеров и маршрутов.
- Usage/audit и бюджеты тенантов.
- Доступность шлюза и upstream-провайдеров.

## Границы доверия

```text
client ──(public, API key)──► gogate ──(admin token, separate port)──► ops
                                  │
                                  ├── PostgreSQL (control plane)
                                  ├── Redis (hot path)
                                  └── upstream providers (admin-configured URLs)
```

- Публичный клиент не доверенный.
- Admin-оператор доверенный, но его действия валидируются.
- Провайдеры считаются внешними и потенциально нестабильными.
- PostgreSQL/Redis считаются доверенной инфраструктурой внутри сети.

## Угрозы и меры

### Кража/перебор API-ключа

- Ключи: 32 случайных байта secret, SHA-256 + pepper, prefix для поиска.
- В БД нет plaintext; в логах ключ не пишется, только `key_prefix`.
- Сравнение хеша constant-time.
- Ключ можно отключить (`enabled=false`) или удалить; snapshot обновляется.
- `expires_at` поддерживается.
- Ограничение RPM/TPM снижает скорость перебора и злоупотребления.

Остаточный риск: утечка ключа через клиентское приложение. Мера — ротация и
квоты.

### SSRF через URL провайдера

- URL задаёт только admin API.
- Публичный API не принимает URL.
- Проверяются scheme (http/https), отсутствие userinfo, host, DNS-резолвинг.
- Блокируются metadata (`169.254.169.254`, `metadata.google.internal`),
  link-local, unspecified, multicast.
- Private/loopback разрешены только при `GOGATE_ALLOW_PRIVATE_UPSTREAMS=true`
  (нужно для локального Ollama).
- HTTP-клиент не следует redirect'ам.

Остаточный риск: DNS rebinding и смена IP после проверки. Для строгих окружений
используйте egress firewall и allowlist.

### Утечка prompt/response в логи или audit

- Prompt/response не логируются.
- Audit хранит только метаданные.
- Ошибки upstream ограничены по размеру; тела не пишутся целиком.
- PII-redaction запроса опционально заменяет email/phone/card.
- Streaming-ответы не редактируются (ограничение, зафиксировано).
- Кэш хранит ответы; exact — в Redis, semantic — в PostgreSQL. Это данные
  тенанта; доступ к Redis/PostgreSQL должен быть ограничен сетью.

### Обход лимитов

- Лимиты проверяются атомарно в Redis Lua по scope tenant и key.
- RPM/TPM резервируются до запроса, затем settlement.
- Дневные и месячные лимиты — отдельные счётчики.
- При недоступности Redis по умолчанию fail-closed.
- Ключи и тенанты изолированы.

Остаточный риск: fail-open при явном включении; мягкий settlement бюджетов.

### Компрометация admin-контура

- Отдельный порт, отдельный роутер, отдельный токен.
- Constant-time сравнение токена.
- Публичный listener не содержит admin routes.
- pprof только по флагу и только на admin.
- Конфиг отдаётся без секретов.
- Секреты провайдеров — только env; в БД хранится имя переменной.
- `api_key_env` ограничен префиксом `GOGATE_UPSTREAM_`, чтобы admin не мог
  прочитать произвольный секрет процесса (`GOGATE_API_KEY_PEPPER`, `AWS_*`).

Рекомендация: не публиковать admin-порт в интернет; использовать VPN/bastion.

### DoS

- Body limit, лимит сообщений/токенов, таймауты чтения/записи.
- `GOGATE_MAX_INFLIGHT` (конфигурируемый) и метрика inflight.
- Rate limit на ключ/тенанта.
- Ограниченные очереди usage/audit; переполнение не блокирует hot path.
- Ограничение размера SSE/JSON чанков и upstream error body.
- Circuit breaker защищает от «залипания» на больном провайдере.

Остаточный риск: распределённый DDoS до балансировщика; нужен edge-защита.

### Инъекции/некорректный ввод

- JSON декодируется с ограничением тела; лишние поля игнорируются.
- Модель должна существовать в control plane; произвольные upstream URL
  невозможны.
- SQL — только параметризованные запросы pgx.
- Lua-скрипты получают данные через ARGV; ключи формируются из внутренних ID.
- Роли сообщений и типы content валидируются.

### Секреты в репозитории

- `.env` генерируется локально и игнорируется git.
- `.env.example` содержит только placeholder'ы.
- CI: gitleaks, govulncheck.
- Провайдерские ключи не хранятся в БД.

## Остаточные риски

- TLS терминируется внешним reverse proxy; без него трафик не шифруется.
- Redis/PostgreSQL должны быть в приватной сети.
- Semantic cache использует embeddings; качество и приватность зависят от
  выбранного embedder.
- Prompt injection — ответственность приложения/модели, не шлюза.
- Логи и метрики могут содержать tenant/model/provider; это не секреты, но
  учитывайте политику хранения.
