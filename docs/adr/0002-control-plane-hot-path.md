# ADR 0002: PostgreSQL control plane, Redis hot path

## Статус

Принято.

## Контекст

Ключи, провайдеры и квоты меняются редко, но читаются на каждом запросе. Поход
в PostgreSQL на каждый chat-запрос добавляет latency и связывает доступность
шлюза с БД.

## Решение

PostgreSQL — источник истины для тенантов, ключей, провайдеров, квот, цен,
usage, audit и semantic cache. На старте и при admin-мутациях строится
immutable snapshot в памяти (`atomic.Pointer`). Auth и роутинг читают только
snapshot.

Redis используется для лимитов, квот и exact cache. Он не является источником
истины: потеря Redis сбрасывает счётчики и кэш, но не конфигурацию.

## Последствия

- Hot path не зависит от latency PostgreSQL.
- Несколько экземпляров работают с общим control plane.
- Изменения в БД, сделанные в обход API, требуют `POST /admin/v1/reload` или
  периодического reload (в текущей версии — admin reload).
- Snapshot должен быть потокобезопасным и атомарно заменяемым.
