# ADR 0004: Rate limiting and quotas

## Статус

Принято.

## Контекст

Нужны RPM и TPM на ключ и тенанта, дневные квоты, месячные бюджеты и корректный
`Retry-After` под конкурентной нагрузкой. Проверка должна быть атомарной.

## Решение

Один Redis Lua-скрипт на admission:

- RPM/TPM — token bucket/GCRA на scope tenant и key;
- дневные запросы/токены — счётчики с TTL;
- месячная стоимость — `INCRBYFLOAT` с TTL;
- резерв `prompt + max_tokens` и оценка стоимости;
- при отказе возвращаются причина и `Retry-After`.

После ответа settlement корректирует резерв по фактическому usage и стоимости.
При недоступности Redis поведение fail-closed по умолчанию.

## Последствия

- Один round-trip в Redis на запрос, атомарность между scope.
- TPM учитывает резерв, поэтому возможен небольшой перерасход при недооценке.
- Бюджеты «мягкие» на settlement.
- Lua-скрипты рассчитаны на один Redis; для Cluster нужна отдельная схема.
