# ADR 0003: API keys

## Статус

Принято.

## Контекст

Ключ должен быть непредсказуемым, пригодным для поиска в БД без хранения
plaintext и безопасным для логов. Нужны быстрый lookup на hot path и
возможность отзыва.

## Решение

Формат: `gk_<env>_<prefix_hex>_<secret_hex>`.

- prefix — 6 случайных байт в hex, хранится открыто и индексируется;
- secret — 32 случайных байта в hex;
- в БД хранится `SHA-256(pepper || secret)`, сравнение constant-time;
- pepper обязателен, задаётся через env;
- plaintext возвращается только в ответе на создание ключа.

Hex выбран вместо base64url, чтобы разделитель `_` не встречался внутри
сегментов и разбор ключа был однозначным.

## Последствия

- Поиск по prefix — O(1) в snapshot/БД.
- Утечка БД не даёт готовых ключей без pepper.
- Ротация pepper инвалидирует все ключи: нужен контролируемый сценарий.
- В логах допустим только `key_prefix`.
