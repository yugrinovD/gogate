# ADR 0007: Async usage and cost

## Статус

Принято.

## Контекст

Запись usage/audit в PostgreSQL на каждом запросе добавляет latency и создаёт
нагрузку на БД при 500+ RPS. При этом потеря небольшого числа записей при
переполнении допустима, если это видно в метриках.

## Решение

Использовать bounded-очереди и фоновый writer:

- usage-записи мержатся по tenant/key/provider/model/day и пишутся батчами;
- audit пишется батчами без содержимого диалога;
- flush по размеру батча или таймеру;
- при переполнении очереди запись дропается, инкрементируется метрика;
- graceful shutdown дрейнит очереди и делает финальный flush.

Cost считается по `model_prices` до записи.

## Последствия

- Hot path не блокируется на PostgreSQL.
- Usage/audit могут отставать на секунды.
- Дропы наблюдаемы, но не ретраятся бесконечно.
- Нужен корректный shutdown-порядок.
