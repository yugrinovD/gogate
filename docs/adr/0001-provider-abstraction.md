# ADR 0001: Provider abstraction

## Статус

Принято.

## Контекст

Шлюзу нужны mock, Ollama и произвольный OpenAI-compatible upstream. Провайдеры
отличаются форматом стрима, полями usage и способом аутентификации.

## Решение

Ввести общий интерфейс `Provider` с методом `Chat(ctx, Request) (Stream, error)`.
Каждый адаптер нормализует ответ в общий `Chunk` (role, content, finish_reason,
usage). Публичный HTTP-слой работает только с нормализованными чанками и
OpenAI-совместимыми DTO.

Registry строит цепочки fallback по модели и priority. Провайдеры создаются из
control plane, секреты upstream читаются из env по имени переменной.

## Последствия

- Новый провайдер добавляется одним адаптером и строкой в БД.
- Streaming/usage/fallback реализованы один раз в оркестраторе.
- Нужно поддерживать нормализацию ошибок (`UpstreamError`) и usage.
- Нет прямой проксировки «как есть»: поля вне общего контракта теряются.
